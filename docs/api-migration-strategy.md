## 🗺️ 단계별 마이그레이션 로드맵

### **1단계: 핵심 인증 및 사용자 기능 전환 (Priority 0)**

1.  **`Auth` API (1순위)**:

    - `POST /auth/signin`: 실제 로그인 API 연동.
    - `client/http.ts`의 인증 헤더 로직 활성화.
    - `refreshToken`을 사용한 토큰 갱신 로직 구현.
    - `POST /auth/signup`, `/auth/signout` 등 구현.

2.  **`User` API (2순위)**:
    - `GET /users/me`: 로그인된 사용자의 실제 정보 조회.
    - `GET /users/courses`, `/users/vouchers`: 사용자별 데이터 조회.
    - API 응답 데이터와 `TypeUser` 등 타입 정의 일치 확인.

### **2단계: 상거래 및 핵심 콘텐츠 전환 (Priority 1)**

1.  **`Order` / `Purchase` API (3순위)**:

    - `POST /orders`: 실제 주문 생성 API 연동.
    - 결제 게이트웨이(PG) 연동 및 테스트.
    - `GET /orders`: 실제 주문 내역 조회.

2.  **`Product` / `Course` API (4순위)**:
    - `GET /products/{id}`, `/courses/{id}`: 실제 상품/강의 데이터 연동.
    - `mock.json`의 중첩된 데이터 구조를 실제 API 응답에 맞게 파싱하는 로직 수정.

### **3단계: 학습 및 프로모션 기능 전환 (Priority 2)**

1.  **`Enrollment` / `Classroom` API (5순위)**:

    - 수강 신청 및 학습 이력 관련 API 연동.
    - 동영상 플레이어(Kollus) 관련 인증 및 API 연동.

2.  **`Voucher` API (6순위)**:
    - 쿠폰 조회, 적용, 다운로드 API 연동.
    - 복잡한 쿠폰 정책(사용 조건, 할인 계산)을 백엔드와 협의하여 클라이언트 로직 최소화.

### **4단계: 콘텐츠 및 부가 기능 전환 (Priority 3, 4)**

1.  **`Display` / `Page` / `Operation` API (7, 8순위)**:

    - CMS(콘텐츠 관리 시스템) 또는 백오피스에서 관리되는 정적/운영 데이터 연동.
    - `getStaticProps` 또는 ISR(Incremental Static Regeneration)을 활용하여 성능 최적화.

2.  **`Search` API (9순위)**:

    - 검색 전용 엔진(예: Elasticsearch, Algolia)과 연동.
    - 자동완성, 검색 필터, 정렬 기능 구현.

3.  **`Exchange` API (10순위)**:
    - Third-party 환율 API 또는 내부 환율 API 연동.

## 🔧 기술적 고려사항 및 권장사항

### 1. **API 클라이언트(`http.ts`) 개선**

- **인터셉터(Interceptor) 도입**: 요청/응답을 가로채 공통 로직(토큰 갱신, 에러 로깅 등)을 처리하는 패턴을 도입하여 코드 중복을 줄입니다.
- **환경 변수 관리**: `apiServer`와 같은 주요 설정은 `.env` 파일을 통해 환경별(개발, 스테이징, 프로덕션)로 관리해야 합니다.

### 2. **상태 관리 전략 고도화**

- **TanStack Query 적극 활용**: `useEffect`와 `useState`로 서버 데이터를 직접 관리하는 대신, `useQuery`와 `useMutation`을 사용하여 서버 상태 관리를 일원화합니다.
    - **장점**: 캐싱, 로딩/에러 상태 자동 관리, `stale-while-revalidate` 등 강력한 기능 활용.
- **Valtio 역할 명확화**: Valtio는 순수 클라이언트 상태(예: UI 상태, 다크 모드) 관리에 집중하고, 서버 상태는 TanStack Query에 위임합니다.

### 3. **에러 처리 전략**

- **중앙화된 에러 처리**: `_fetch` 함수에서 잡힌 에러를 공통 에러 객체로 정규화하고, `ErrorBoundary` 컴포넌트나 `useQuery`의 `onError` 콜백을 사용하여 사용자에게 일관된 에러 피드백을 제공합니다.
- **HTTP 상태 코드 분기**: 401(Unauthorized), 403(Forbidden), 500(Internal Server Error) 등 주요 상태 코드에 따른 분기 처리 로직을 구현합니다. (예: 401 수신 시 자동 로그아웃)

### 4. **Mock 데이터 유지 및 관리**

- **Storybook 연동**: 마이그레이션 과정에서 UI 컴포넌트의 독립적인 개발과 테스트를 위해 Storybook에 Mock 데이터를 연동하여 활용합니다.
- **MSW (Mock Service Worker)**: `json-server` 대신 MSW를 도입하면, 실제 API 요청을 가로채 모의 응답을 제공하여 더 실제와 가까운 환경에서 개발 및 테스트가 가능합니다.
